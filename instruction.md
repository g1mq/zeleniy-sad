## 3. День экзамена: порядок действий

**За 15–30 минут до демонстрации:**

- [ ] Прочитать **новое ТЗ** (название фирмы, цвета, логины, товары).
- [ ] Заменить данные по [разделу 4](#4-замена-данных-из-нового-задания).
- [ ] В pgAdmin создать БД, если другое имя (или оставить `green_garden`).
- [ ] `cd app` → `npm run db:reset` → перезагрузить данные.
- [ ] Запустить `zapusk.bat`, проверить [раздел 10](#10-проверка-перед-сдачей).
- [ ] Открыть Figma / PDF ER, если спрашивают блок 1–2.

**Во время демонстрации:** войти под 4 ролями (гость, клиент, менеджер, админ).

```js
  green: '#22C55E',   // из брендбука ТЗ
  brown: '#8B7355',
  yellow: '#FCD34D',
  cream: '#F8FAF5',
},
```

**Файл:** `app/public/css/app.css` — в начале блок `:root` те же hex-цвета.

**Слоган на экране входа:** `app/public/js/app.js` — строка с текстом «Природа в вашем доме» (поиск по файлу: `Природа`).

---

### 4.2. Логотип

1. Сохраните новый файл как:  
   `app/public/images/logo.png`  
2. Скопируйте туда же в:  
   `prototype/images/logo.png`  
3. Имя файла не меняйте — только замените картинку.

---

### 4.3. Пользователи (логины, пароли, ФИО)

**Файл:** `database/seed.sql` — блок `INSERT INTO users`.

**Важно:** в БД хранится **не пароль**, а **SHA-256 хеш**.

#### Как получить хеш пароля

В папке `app` в командной строке:

```bash
node scripts/hash-password.js "ПарольИзТЗ"
```

Скопируйте длинную строку из вывода в `password_hash` в `seed.sql`.

**Пример** (подставьте свои данные из ТЗ):

```sql
INSERT INTO users (login, password_hash, role_id, full_name, phone) VALUES
  ('admin_новый', 'СЮДА_ХЕШ_ПАРОЛЯ',
   (SELECT id FROM roles WHERE role_name = 'admin'), 'Фамилия А.А.', '+7 ...'),
  ('manager_новый', 'ХЕШ',
   (SELECT id FROM roles WHERE role_name = 'manager'), 'Фамилия Б.Б.', '+7 ...'),
  ('client_новый', 'ХЕШ',
   (SELECT id FROM roles WHERE role_name = 'client'), 'Фамилия В.В.', '+7 ...')
ON CONFLICT (login) DO NOTHING;
```

Роли `guest`, `client`, `manager`, `admin` **не удалять** — они нужны системе.

---

### 4.4. Товары

**Файл:** `database/seed.sql` — блок `INSERT INTO products`.

Поля из ТЗ:

| Поле | Допустимые значения |
|------|---------------------|
| `type` | `seed`, `seedling`, `plant`, `bulb` |
| `price` | больше 0 |
| `quantity` | 0 или больше |

Меняйте: `article`, `name`, `brand`, `price`, `quantity`, `category`, `description`, `planting_season`.

После смены артикулов обновите связи в `product_condition_link` (внизу `seed.sql`) — в условиях `WHERE p.article = 'ВАШ_АРТИКУЛ'`.

---

### 4.5. Условия выращивания

**Файл:** `database/seed.sql` — `INSERT INTO growing_conditions`.

Четыре поля: `climate_zone`, `soil_type`, `sunlight`, `watering` — как в ТЗ (климат, почва, освещённость, полив).

---

### 4.6. Заказы

**Файл:** `database/seed.sql` — блоки `INSERT INTO orders` и `order_items`.

- В заказе используйте **логин клиента** через подзапрос:  
  `FROM users u WHERE u.login = 'client_новый'`
- В позициях заказа — **артикул товара**:  
  `JOIN products p ON p.article = 'FL-ROSE-001'`

Либо на экзамене создайте заказы **вручную в приложении** под админом (меню «+ Заказ»).

---

### 4.7. Применить новые данные в PostgreSQL

После любых правок `seed.sql` или `schema.sql`:

```bash
cd app
npm run db:reset
```

⚠️ **`db:reset` удаляет все таблицы и создаёт заново.** Старые данные пропадут — на экзамене это нормально.

Затем снова: `npm start` или `zapusk.bat`.

---

### 4.8. Другая база или пароль PostgreSQL

**Файл:** `.env` (в корне `ZeleniySad`)

```env
PGDATABASE=имя_базы_из_ТЗ
PGPASSWORD=ваш_пароль
```

В pgAdmin: **Create Database** с тем же именем.

## 5. PostgreSQL

### Перед экзаменом (дома)

1. Установить PostgreSQL с [postgresql.org/download/windows](https://www.postgresql.org/download/windows/).
2. Запомнить пароль пользователя `postgres`.
3. Создать базу: `CREATE DATABASE green_garden;` (или как в `.env`).
4. Проверить службу: `Win+R` → `services.msc` → **postgresql** → «Выполняется».

### На экзамене

- PostgreSQL и Node.js должны быть **уже установлены** на ноутбуке.
- Интернет для работы приложения **не нужен** (шрифты Google — если нет сети, подставятся системные).

### pgAdmin — полезные запросы

```sql
-- Все пользователи и хеши (для эксперта)
SELECT login, password_hash, full_name FROM users;

-- Товары
SELECT * FROM products;

-- Проверка внешних ключей: попробовать удалить товар из заказа
-- (должна быть ошибка, если товар в order_items)
```

## 10. Проверка перед сдачей

Отметьте галочками:

### Гость
- [ ] Вход без логина  
- [ ] Каталог открывается  
- [ ] **Нет** поиска и фильтров  
- [ ] **Нет** пункта «Заказы»

### Клиент
- [ ] Вход по логину/паролю из ТЗ  
- [ ] Каталог без фильтров  
- [ ] **Нет** заказов

### Менеджер
- [ ] Есть поиск и фильтры  
- [ ] Есть «Заказы», просмотр деталей  
- [ ] Можно сменить статус  
- [ ] **Нельзя** удалить заказ / редактировать товары

### Администратор
- [ ] CRUD товаров (добавить, изменить, удалить)  
- [ ] CRUD заказов  
- [ ] Регистрация нового клиента + CAPTCHA  

### База
- [ ] `SELECT password_hash FROM users` — длинные hex-строки, не «123456»  
- [ ] ER PDF готов  
- [ ] Figma ссылка работает

## 11. Частые ошибки

| Проблема | Решение |
|---------|---------|
| Сайт не открывается | PostgreSQL запущен? `npm start` без ошибок? |
| `password authentication failed` | Пароль в `.env` = пароль postgres |
| `database does not exist` | Создать БД в pgAdmin, имя как в `.env` |
| Вход не работает после смены пароля | Пересчитать хеш: `node scripts/hash-password.js "пароль"` → вставить в `seed.sql` → `npm run db:reset` |
| Старые товары в каталоге | Забыли `npm run db:reset` после правки seed |
| Эксперт видит пароль в открытом виде | Должен быть только `password_hash` в таблице `users` |
| У гостя есть фильтры | Войти именно как гость, не как клиент |
